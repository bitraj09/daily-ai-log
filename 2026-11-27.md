# 2026-11-27 — Prompt engineering: few-shot examples and chain-of-thought

## Concept

Attention (Day 6) decides what a model looks at — and the **prompt** is what tells it where to look. Prompt engineering is the skill of writing that instruction well, and two patterns do most of the work.

**Few-shot prompting** means showing the model a few worked examples before asking the real question: `Q: ... A: ...` pairs that teach the format and the vocabulary in context, without any training. The model generalises from the examples — which is also the risk: a wrong or misleading example teaches the wrong thing, just as confidently.

**Chain-of-thought (CoT)** means asking the model to reason step by step before giving its final answer ("Think step by step, then give the final label."). The reasoning tokens give attention something to work with: the model can break the question down, weigh the evidence, and only then commit — instead of jumping straight to a label. It helps most on multi-step questions, and helps least on questions that are already one step.

Both are the same idea as RAG (Day 1): you don't change the model's weights, you change what it sees. RAG changes the retrieved context; prompting changes the instruction and the examples around the question.

## Code — zero-shot vs few-shot, with a toy stand-in

A real LLM does this with learned weights, not keywords — so the scorer below is a deliberately tiny stand-in: it counts keyword overlap between the question and each label. What it *does* show honestly is the mechanism: the few-shot examples add vocabulary to the context, and that changes the answer.

```python
def build_prompt(task, examples, question, cot=False):
    """Assemble a prompt: task + few-shot examples + the real question."""
    lines = [f"Task: {task}", ""]
    for q, a in examples:
        lines.append(f"Q: {q}\nA: {a}")
    if cot:
        lines.append("Think step by step, then give the final label.")
    lines.append(f"Q: {question}\nA:")
    return "\n".join(lines)

# Toy stand-in scorer: keyword overlap only (NOT a real LLM).
LABELS = {
    "diagnosis": ["diagnose", "disease", "symptom"],
    "treatment": ["treat", "filling", "procedure"],
    "anatomy":   ["tooth", "diagram", "structure"],
}
# What the few-shot examples teach, in context: new keywords per label.
FEWSHOT_EXTRA = {
    "diagnosis": ["pain", "cold", "hurts", "sensitive"],
    "treatment": ["filling", "crown", "root", "canal"],
    "anatomy":   ["molar", "enamel", "root"],
}
EXAMPLES = [
    ("sharp pain when drinking cold water", "diagnosis"),
    ("cavity needs a filling", "treatment"),
    ("molar has three roots", "anatomy"),
]
QUESTION = "my tooth hurts when I drink cold water"

def classify(question, extra=None):
    words = set(question.lower().split())
    scores = {}
    for label, kws in LABELS.items():
        k = list(kws)
        if extra:
            k += FEWSHOT_EXTRA.get(label, [])
        scores[label] = sum(1 for w in words if w in k)
    return scores

task = "Classify the dental query as diagnosis, treatment or anatomy."
print("=== zero-shot prompt ===")
print(build_prompt(task, [], QUESTION))
zero = classify(QUESTION)
print("scores:", zero, "->", max(zero, key=zero.get))
print()
print("=== few-shot + chain-of-thought prompt ===")
print(build_prompt(task, EXAMPLES, QUESTION, cot=True))
few = classify(QUESTION, extra=True)
print("scores:", few, "->", max(few, key=few.get))
# Expected: zero-shot picks "anatomy" (only "tooth" matches, score 1);
# few-shot picks "diagnosis" (hurts + cold match, score 2).
```

## Try it

Delete the `EXAMPLES` from the few-shot prompt and re-run: the answer flips back to the wrong label, "anatomy" — the same question, the same toy model, a different result, purely from the prompt. Then change the question to `"cavity needs a filling and crown"` and re-run with the examples: the few-shot version now picks "treatment" (score 2). One honest limit of this toy: it cannot show chain-of-thought working — the CoT line changes the prompt text, but a keyword scorer has no reasoning to do. In a real LLM, that line matters because the model generates its own intermediate steps before answering; here, take the CoT prompt shape from the code, not the scores.
