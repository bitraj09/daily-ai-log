# Day 5: Embeddings & Vector Search

## Concept
Embeddings turn text (or images, audio) into dense vectors — lists of numbers — where similar meanings sit close together in vector space. A model like `all-MiniLM-L6-v2` maps a sentence to a 384-dimensional vector, and cosine similarity between two vectors tells you how related they are. Vector search stores those embeddings in an index (FAISS, Chroma, pgvector) and retrieves the nearest neighbours for a query, which is exactly the retrieval step that powers RAG: instead of keyword matching, you find documents by meaning.

## Snippet
```python
from sentence_transformers import SentenceTransformer
import numpy as np

model = SentenceTransformer("all-MiniLM-L6-v2")
docs = ["How do I reset my password?", "What is the refund policy?", "How to change my email?"]
emb = model.encode(docs, normalize_embeddings=True)
query = model.encode(["I forgot my login password"], normalize_embeddings=True)
scores = emb @ query[0]  # cosine similarity (vectors are normalised)
print(docs[int(np.argmax(scores))], "->", round(float(np.max(scores)), 3))
```

## Takeaway
Retrieval quality is decided by the embedding model and the chunking, not just the LLM — a good embedding makes RAG answers grounded, a bad one makes the model guess.
