# 2026-11-26 — Attention: how a transformer decides what to look at

## Concept

Embeddings (Day 5) turn text into vectors — but a vector on its own has no
context. **Attention** is the step that gives it context: for each token, the
model looks back at the other tokens and asks, "which of you matter for me
right now?" — then builds a new representation as a weighted mix of the ones
that matter most.

Scaled dot-product attention does this in three moves. Every token gets three
vectors: a **query** (what am I looking for?), a **key** (what do I contain?),
and a **value** (what do I actually contribute?). The **score** between a query
and a key is their dot product — high when they point the same way, low or
negative when they don't. The scores are divided by `sqrt(d)` (where `d` is
the vector size) and passed through a **softmax**, turning them into weights
that sum to 1. The output is the weighted sum of the values.

Two details matter in practice. First, the `sqrt(d)` scaling: without it, dot
products grow with dimension, softmax saturates, and the model stops learning
— one token hogs all the weight. Second, attention weights are **soft**, not a
hard pick: even the least relevant chunk keeps some weight, which is why the
output below is a blend, not a copy of the top chunk.

This is the mechanism inside every LLM, including the ones behind the RAG
pipeline from Day 1: the retriever (Day 5) picks the passages, and attention
inside the model decides, token by token, which parts of those passages to
actually use when it writes the answer.

## Code — scaled dot-product attention in pure Python

```python
import math

def softmax(xs: list[float]) -> list[float]:
    """Turn scores into weights that sum to 1."""
    m = max(xs)
    exps = [math.exp(x - m) for x in xs]
    s = sum(exps)
    return [e / s for e in exps]

def attention(query, keys, values):
    """One query attending over a few key/value pairs."""
    d = len(query)
    scores = [
        sum(q * k for q, k in zip(query, key)) / math.sqrt(d)
        for key in keys
    ]
    weights = softmax(scores)
    out = [
        sum(w * v[i] for w, v in zip(weights, values))
        for i in range(len(values[0]))
    ]
    return scores, weights, out

# Toy 3-D vectors: query = "how to diagnose a tooth cavity?"
query = [1.5, 0.2, 0.1]
keys = {
    "dental filling procedure": [1.4, 0.2, 0.2],
    "tooth anatomy diagram":    [0.3, 1.2, 0.1],
    "football match report":    [-0.3, 1.4, 0.0],
}
# Values: [diagnosis relevance, treatment relevance] of each chunk.
values = [[0.9, 0.8], [0.7, 0.2], [0.0, 0.1]]

names = list(keys)
scores, weights, out = attention(query, [keys[n] for n in names], values)
for name, score, weight in zip(names, scores, weights):
    print(f"{name:28s} score {score:.3f}  weight {weight:.3f}")
print("attended output:", [round(x, 3) for x in out])
# Expected: dental filling procedure first (weight 0.591),
# football report last (weight 0.154); output [0.71, 0.539].
```

## Try it

Double the query to `[3.0, 0.4, 0.2]` and re-run: the dental chunk's weight
jumps to 0.798 and the football chunk drops to 0.054 — a stronger query
sharpens the focus. Then remove the `/ math.sqrt(d)` scaling and notice the
weights sharpen to 0.752 / 0.175 / 0.073 even for the same vectors: in a real
model with hundreds of dimensions, that unscaled sharpening saturates the
softmax and kills learning, which is exactly why the scaling is there.
