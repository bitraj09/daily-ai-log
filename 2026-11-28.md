# 2026-11-28 — Evals: how to tell if your LLM actually got better

## Concept

LoRA (Day 4) changes the weights, prompting (Day 7) changes what the model
sees — but neither tells you whether the model actually got better. That is
what an **eval** is for: a fixed, held-out set of questions, scored the same
way every time, so base vs fine-tuned is a fair comparison instead of a vibe.

Three things make an eval honest. **Held-out data:** the eval questions must
not be in the training set, or the model is just reciting what it memorised.
**A fixed scorer:** the same rule extracts and grades every answer, so you
cannot quietly re-grade the ones you like. **Two numbers, not one:** accuracy
(how often the letter is right) and format adherence (how often the answer
comes back in the expected shape, e.g. `The correct answer is D:`). A model
can know the answer and still fail the eval if its output cannot be parsed —
and fine-tuning often fixes the format before it fixes the knowledge.

The trap is sample size. On 8 questions, one lucky guess swings accuracy by
12.5 points, so a small eval can "prove" almost anything. That is why the
medical-LLM demo in `bitraj09/medical-llm-finetune` evaluates on 200 held-out
MedQA questions, not 8: the same base-vs-adapter comparison, with a gap that
is much harder to explain away by luck. Always report the eval size next to
the score — a number without its `n` is not a result.

## Code — base vs fine-tuned on 8 toy questions

The scorer below is deliberately tiny: it pulls the first standalone letter
A–D out of each answer and checks the format with a prefix test. What it
*does* show honestly is the mechanism: the fine-tuned answers are both more
accurate and consistently parseable, while the base answers mix formats and
miss more often. The numbers are from this exact snippet, run and verified.

```python
import re

GOLD = ["D", "A", "B", "C", "A", "D", "B", "C"]
BASE = ["The answer is D", "B", "B", "I think C",
        "B", "C", "A", "D"]
TUNED = ["The correct answer is D: Nitrofurantoin.",
         "The correct answer is A.", "The correct answer is B.",
         "The correct answer is C.", "The correct answer is A.",
         "The correct answer is B.", "The correct answer is B.",
         "The correct answer is C."]

def letter(ans):
    """First standalone A-D in the answer, or None if unparseable."""
    m = re.search(r"\b([A-D])\b", ans)
    return m.group(1) if m else None

def evaluate(preds):
    correct = sum(1 for g, p in zip(GOLD, preds) if letter(p) == g)
    fmt = sum(1 for p in preds if p.startswith("The correct answer is "))
    return correct, fmt

for name, preds in [("base", BASE), ("fine-tuned", TUNED)]:
    correct, fmt = evaluate(preds)
    print(f"{name}: accuracy {correct}/8 = {correct/8:.1%}, "
          f"format {fmt}/8")
# Expected (verified): base 3/8 = 37.5%, format 0/8;
# fine-tuned 7/8 = 87.5%, format 8/8.
```

## Try it

Change one fine-tuned answer to `"I think B"` and re-run: accuracy stays
7/8 (the letter is still right) but format drops to 7/8 — the same knowledge,
a worse score, purely because the scorer can no longer rely on the shape.
Then shrink the eval to the first 2 questions and re-run: both models score
1/2, and the 50-point gap vanishes — not because the models changed, but
because `n = 2` cannot measure anything. That is the whole lesson: fix the
set, fix the scorer, report both numbers and the `n`.
